# 待开发：API 模型能力自动识别、验证与智能任务分配

- 记录日期：2026-10-08
- 所属项目：Product Video Studio（PVS）
- 类型：模型设置 / 模型路由 / 生产前检查（非完整 Agent 架构改造）
- 优先级：高（影响用户 API 接入后生产能力与质量）
- 状态：**待设计与开发**，本次只记录，不改代码、不测试付费 API、不修改用户模型设置

## 一、用户确认的目标

用户只需要接入一个或多个第三方 API（地址和 Key），无须知道哪种模型适合研究、编剧、分镜、视觉审核或音频审核。

PVS 自动完成「发现模型 → 初步识别能力 → 必要时调用**同一个 API 内可用的文本模型**辅助分类 → 有预算地实际测试 → 为制作环节分配最合适模型 → 记录结果并持续调整」。**不依赖预装、固定指定或额外购买一个识别模型；没有模型接入时，设置页面仍可运行并展示能力缺口。**

默认采用**智能自动分配**，保留用户可以完整指定各步骤模型的手动模式；自动模式提供「均衡 / 质量优先 / 经济优先」偏好及可审计的选择理由。

## 二、识别能力时的可靠性边界

1. **发现**：请求用户服务商模型列表，读取模型 ID 和实际提供的能力、输入输出类型、上下文/价格等元数据（如果可得）。对模型名做规范化和可信服务商映射，但绝不把名称关键词直接认定为已验证能力。
2. **API 内模型辅助识别**：优先从用户已启用且可用的模型中，以元数据和小型文本测试确定可调用的识别助手，再按证据分析同一 API 中其他模型的*可能能力*、适用任务和不确定项。AI 的回答只作为候选分类，不当成实际验证结论；避免单模型自评、凭空判断最新模型或虚构价格。若无法找到可用文本助手，仍能依靠非 AI 的元数据、已知可信资料及提示完成初筛，未知保持 UNKNOWN。
3. **验证**：对可能承担生产任务的少数候选模型进行标准化实际测试，至少区分 TEXT、VISION（识图）、OCR、AUDIO（音频理解）、VIDEO（原生视频理解或明确标注只能抽帧）、STRUCTURED_JSON。使用已知答案、可核对的测试素材和 PVS 真实请求格式；接口成功不代表任务质量合格。
4. **状态区分**：每个「服务商+模型 ID+配置/权限版本+能力」分别记录 VERIFIED、DECLARED、UNSUPPORTED、UNKNOWN、TEMP_UNAVAILABLE 等状态，包含数据来源、测试证据、最近测试时间、错误原因和有效期。429、超时、服务异常和权限不足不能误判成永久不支持。
5. **成本约束**：API 列表发现可在用户请求接入时运行；**任何可能计费的 AI 识别和模型能力测试，都须预先展示测试模型数、费用估计/未知风险及上限，并征得用户明确同意**。对大量模型（历史曾返回 417 个）先筛选已启用/可能使用的候选，不能逐一测试或无限重试。
6. **版本管理**：缓存能力档案；当用户更新 API、服务商公开能力、模型权限、模型 ID 或测试过期时重新评估受影响项，历史版本与审计可查询。

## 三、任务到模型的自动分配

按每个实际生产环节声明硬性能力和质量目标，先通过**硬性能力 Gate**，再对合格模型综合评分；不能把不具备能力的文本模型当作视觉或音频审核模型。

| PVS 工作环节 | 能力要求与评分重点 |
|---|---|
| 产品事实 / 使用规则 | 文本结构化、事实抽取；输入包含需直接识别的产品图片时增加已验证 VISION |
| 联网研究 / 竞品分析 | 证据整理、长文本、推理与引用约束；需要图像/视频时按实际模态增加能力 Gate |
| 创意方案 | 创造性、产品关联、营销表达、可生成性和成本 |
| 剧本 / 导演分镜 / Seedance 提示词 | 叙事逻辑、镜头/时长约束、结构化输出与禁改项执行 |
| 参考视频 / 视频画面分析 | 经验证的 VISION+帧处理，若要求真实原生视频理解须有相应能力；不能把抽帧当成完整视频理解 |
| 视觉审片 | 经验证的 VISION、产品一致性与违规/缺陷识别，置信度不足时人工审核 |
| 声音质量 / BGM 检测 | 经验证的 AUDIO，需真实音频输入且能分辨对白/环境音/BGM；缺失不可由纯文本输出冒充试听 |
| 抖音运营 | 文本、数据分析和评论理解；回复发布继续由人工确认 |
| Seedream/Seedance 图片与视频生成 | 维持独立即梦模型及积分授权链路，不和 AIHubMix 大语言模型测试/路由混用 |

1. 为每个环节在通过 Gate 的候选中，根据**该任务专属**的质量、稳定性、响应速度、价格与历史表现选择；一个模型可以胜任多个任务，不强求每个模型平均消耗。
2. 主观任务的创意/剧本质量需标准化样题与可审计评分，AI 评分为辅助证据，避免单个模型评判所有竞争者或偏向自己；无法可靠评分时标记不确定。
3. 三种模式：**自动·均衡（默认）/ 自动·质量优先 / 自动·经济优先**，另有完整手动步骤覆盖；用户手动覆盖仍须执行必要能力与预算 Gate。
4. 执行失败时只在同能力已验证、预算允许的模型中有限重试/降级；切换原因留痕，无法满足硬性能力时暂停，不静默切到不合格模型，不产生意外付费。
5. 在每次执行记录中显示：**实际使用的模型/服务商、步骤、选型原因、是否能力回退、成功失败、耗时、Token 和真实或估算费用（可得时）**。不能只展示用户“计划选择”的模型；服务商账单与 PVS 统计口径需明确区分。

## 四、缺失必要能力的用户体验

- API 全为 TEXT，仍允许文本研究、剧本等兼容工作，但进入需 VISION 的实际图片理解步骤前明确提示「当前 API 没有经验证可识图模型」，说明受影响环节和添加/验证入口。
- AUDIO 缺失、未知或接口不支持真实音频时，音频审核必须停在待补齐/待人工审核状态，不可因返回一段文本就声称已经听到声音；原生音乐检测亦如此。
- OPTIONAL 能力缺失仅使对应增强步骤降级，并解释降级范围；REQUIRED 能力缺失必须阻止该步骤，不随意阻断无关任务。
- 异常提示全部用中文；高级日志可查询协议响应/能力标签及测试原因，但不泄漏 API Key 或用户敏感素材。

## 五、基线与实施级拆分

现有 `AiSettingsService`、`AiRuntimeRouter`、`AiSettingsRepository`、模型能力标签及 `AiExecutionRecord` 为改造基础；当前主要靠项目步骤覆盖 → 项目默认 → 系统默认 → 服务商默认，以及视觉/音频能力后备；曾观察到「AIHubMix 默认 deepseek-v4.1-flash，多个模型已启用但无步骤分配」，且部分能力由名称推断，尚不能表示已验证。

- **阶段 A：方案/基线审计**：列出 PVS 真实步骤及所需能力、区分文字任务/抽帧/音频/生成工具；检查模型列表接口差异、已存默认值、步骤覆盖和计费范围。
- **阶段 B：能力发现与缺口 Gate**：元数据导入、UNKNOWN/DECLARED 标签、自动/手动模式及中文缺口提醒，先保证不误用模型。
- **阶段 C：受控验证**：在用户逐次或按固定预算明确授权后，选择 API 内可用文本模型辅助识别并对少数候选执行图片、OCR、音频、结构化 JSON 等真实测试；建立可复用版本化证据。
- **阶段 D：自动分配**：按任务、质量模式和预算进行自动路由、同能力故障后备和分配方案预览；支持人工覆盖、撤回与还原。
- **阶段 E：可观察性与 E2E**：调用实况、Token/费用（服务商可得时）、质量/成本持续评估、生产前能力完整性检查和多 Provider 回归。

## 六、验收 Gate

1. 新用户只连接 API 后，无需手动选择每步模型；系统有依据地给出初步分工并明确**已验证与待验证**，不能夸大能力。
2. 纯 TEXT API 不会在图片/音频必要任务中悄悄调用文本模型；错误清楚说明缺少什么，文本任务可以继续。
3. 同 API 同时存在文本/视觉/音频候选时，按实际测试证据分配；支持手动覆盖，但不能绕开硬性能力/新付费授权。
4. 417 个模型级别的列表不会自动触发数百次付费调用；测试前有预算/未知费用提示，取消后费用为零。
5. 视觉识图、音频 BGM/对白检查必须经真实多模态输入验证；不允许纯文字“猜测”的结果冒充已听/已看。
6. 同一模型可负责多个环节；当模型不可用时同能力有界降级并记录原因，不能擅自追加扣费。
7. 单元测试覆盖能力筛选、服务商元数据差异、未知/限流状态、费用门禁、手动覆盖；集成与真实 API E2E 验证并保留回归日志。
8. 既有 Product Video Studio 智能生成/手动生成、Seedream/Seedance 积分/声音和项目历史不因路由升级被破坏。
