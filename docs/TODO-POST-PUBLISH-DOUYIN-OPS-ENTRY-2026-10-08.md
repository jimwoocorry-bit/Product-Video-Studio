# 待开发：发布完成后显示「进入抖音运营」按钮

- 记录日期：2026-10-08
- 所属项目：Product Video Studio（PVS × 抖音运营）
- 状态：**已实现并通过单元与隔离浏览器 E2E；真实平台不重复发布，可信回执条件下才显示**
- 所在页面：项目「成片 / 发布」页 `/projects/:projectId/final`

## 用户需求

用户在**作品发布完成后**，希望页面**最下面**显示一个明显的按钮：

**「进入抖音运营」**

点击后直接跳转到**当前项目对应的抖音运营页面**，而非重新打开视频发布流程。

## 实施约束

1. 按钮放在本项目成片 / 发布页面的**内容最底部**，位于发布结果、发布记录等内容之后；采用正常可点击导航按钮样式，保持中文标签「进入抖音运营」。
2. 现有目标路由已确认：`/projects/:projectId/douyin`（对应项目的「发布后表现 / 抖音作品绑定 / 数据 / 评论 / AI 复盘」）；不要误跳全局运营首页 `/douyin-ops`，也不要生成不存在的 `/projects/:id/douyin-ops` 路由。
3. **完成判据**：只有作品经平台可信回执确认为 `PUBLISHED_CONFIRMED` 或相应可信的最终发布确认状态，才以「发布完成」展示该按钮。仅创建发布包、交接完成、等待用户发布、提交结果未知等状态不算发布成功。手动导出/手动发布若无法可信确认，也不应冒充已发布。
4. 点击按钮只做页面跳转，携带当前 projectId；不得重复发布、重新生成视频、自动绑定账号、自动同步数据、自动发评论，或引入任何额外付费动作。
5. 跳转后即使运营账号未登录或运营连接不可用，也应进入当前项目运营页展示真实状态及已保存数据，并给予可理解的登录/连接提示，不应误报账号正常或作品已绑定。
6. 保留现有页面「下载 MP4」、发布记录及审核信息；只新增入口，不破坏原发布工作流。

## 验收用例

- 平台可信确认发布后，刷新项目成片 / 发布页，在**最下方**出现且仅出现一个「进入抖音运营」按钮；点击可访问 `/projects/:projectId/douyin`。
- 发布包刚创建、等待扫码、交接完成但未确认发布，以及结果未知时，不把作品误标成发布成功，也不展示“发布已完成”的入口。
- 跨两个项目时，按钮跳转保持正确 projectId，不进入其他作品的数据页。
- 抖音运营连接异常时，按钮仍可进入项目运营页检查状态，不自动触发外部操作。
- 页面/路由相关测试和既有发布门禁回归通过。
