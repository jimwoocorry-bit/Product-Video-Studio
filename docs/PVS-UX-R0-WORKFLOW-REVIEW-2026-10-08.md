## 1. 首先纠正上一轮验收口径

上一轮 W0–W4 在本地记录了 476/476 单元/集成与 20/20 浏览器用例通过。**通过的是写入测试的预期，不是整体可用性。**

具体反例：
1. src/web/smart-generation-ui.ts 把完整 research/reference-video/creative-references 页面作为 iframe 放入当前页；待审事实/视频/成片也是完整页面 iframe。原页面包含顶栏和导航，直接导致页面套页面、重复导航与滚动区。
2. tests/e2e/workflow-w2-w4.spec.mjs 明确对 iframe/src 做正向断言：测试把错误交互方案当成正确实现。
3. src/application/services/workflow-navigation.ts（传统 9 步、Project.status）与 src/application/services/workflow-next-action.ts（SmartRun 13 阶段、21 状态）同时生成导航/下一步信息；旧页面和智能生成页不一定表达同一个用户任务。
4. smart-generation-ui.ts 对活跃审片 Run 仍展示六种“这次想完成什么”的新任务选项，并显示完整剧本、分镜、Prompt、资产、音轨，真正待审动作不在首屏。
5. 产品页/参考页/单片段页显示基于 Project.status 的“当前要做”，并非当前页实际操作。历史已发布 + 新任务审片可同时成立，但 UI 混成单一“已发布”标签。
6. 部分操作要求用户在完整外部页或 iframe 内提交、关闭再手动点击“刷新本轮内容/问题处理后继续原任务”，没有统一确认后续接。
7. 视频模型“不生成 BGM”与后期 Timeline 已选 BGM 混在同一层解释，用户不易理解最终输出。
8. 模型能力分配是独立待办：模型设置仍允许文本类模型出现在图片理解相关步骤候选；未来需能力检查和中文提示，但本轮不偷做全新自动路由架构。

根因归纳：上一轮实施的是“导航胶水 + 内嵌完整旧页面”，不是一个围绕当前任务的统一工作台；交互验收被技术路径断言取代。

### 已解决的设计分歧

- **“所有操作必须同一页” vs “专业操作需要空间”**：选择一个任务工作台作为主入口，同源局部面板/抽屉作为默认方式；复杂专业编辑可打开独立页面，但带严格 taskId + step + itemKey 回程。**不能使用完整页 iframe**。
- **“再造完整状态机” vs “继续打补丁”**：两者都否。保留底层既有状态机，新建唯一用户层 Presentation/Action Resolver；旧 Legacy 项目由兼容适配器投影到同一用户语言。
- **“从零重写前端” vs “沿用全部旧 UI”**：按页面模块渐进提取 view/component；复用原服务和审查 API；同时淘汰原有默认的重复导航/嵌套布局。
- **“自动做完一切” vs “每步手工确认”**：合法、可恢复的非付费动作默认自动推进；产品事实、创意选择、必要固定资产、真实费用、低置信镜头、成片和真实发布/绑定必须显式确认；旧用户选择过的专家模式继续兼容。

## 3. 产品层级和最终页面结构（冻结候选）

### 全局层（非项目）
- **项目**：创建/打开项目，显示项目名、最新已确认成片、历史发布信息。
- **当前任务**：进入/恢复当前任务；按需查看多任务与历史，不再维护另一个重复的“智能生成项目列表”。
- **发布后运营**：对应真实作品、账号、数据、评论和复盘；仅可信发布确认后联通。
- **设置与诊断**：AI 连接/模型能力、系统状态；不占主任务首屏。

### 项目工作台（唯一主入口）
顶部：项目名 + 当前任务名/制作目的 + 目标时长 + 当前具体阶段 + 明确“已发布的是哪一版”。  
左侧/顶部进度：按用户可理解的 6 组呈现，内部映射到现有 13 阶段；可选步骤显示“已跳过/可补充”，不是都要求经过。  
中央主区域：当前待办（创意选择、资产看图、镜头审片等）及其唯一主动作。  
右侧或可展开：素材、版本历史、专业编辑、执行日志、模型参数。  
底部：安全停止、返回项目、人工恢复、联系客服/诊断；技术英文与哈希默认折叠。

六组视图（不是新的六状态后端）：
A 产品与事实 → B 创作准备（按需研究/参考、创意）→ C 制作准备（策略、资产、脚本、分镜、Prompt）→ D 视频（预检/费用/生成/审片）→ E 后期成片（声音/Timeline/渲染/QC/确认）→ F 发布与运营（独立可选）。  
剧本/分镜的精细编辑为 C 内的子工具，最终生成依据仍由 Director V3 统一编译。

### 六种用户目标入口（只在创建新任务时展示）
1. 新做完整视频：输入要求 → 产品事实 → 可选研究/参考 → 创意 → 资产/剧本/分镜 → 镜头 → 成片。
2. 研究同类爆款再制作：在 B 阶段先研究/选择样本与明确可用素材 → 参考绑定版本 → 继续当前创意；竞品信息不自动成为产品真值。
3. 用自带参考视频：上传 → 分析 → 确认引用 → 绑定当前任务 → 继续创意/分镜；不再需要单独“导入智能生成”手工串联。
4. 只生成单片段：独立轻量子流程，材料/模型/成本/生成/结果确认；不强制完整剧本与成片流程。
5. 已有素材只重剪：选择已采用镜头或已有 Timeline → 剪辑/声音/质检/渲染；不重做产品、剧本、素材。
6. 已有成片只发布：选择真实已确认 MP4 → 检查及发布确认 → 可信回执 → 运营；不能把交接/扫码视为“已发布”。

已有活跃任务时，首页**不再显示六个目标入口**，只显示“继续当前任务”和次级“切换/新建任务（会检查冲突）”。

## 4. 统一状态与跳转技术契约（冻结候选）

建议新增服务层 **WorkflowPresentationResolver / WorkflowReadModel**，只读组合，不改 SmartRun 生成状态机。

统一响应应至少包含：
- projectId；当前 task/run 的明确 ID、kind（SMART_RUN/LEGACY/SINGLE/EDIT/PUBLISH）、intent；如多个进行中任务必须显示可选列表，不按“最后更新”静默替用户选错。
- phase/currentStep/stepStatus：阶段、已完成、可选、已跳过、执行中、等待用户、失败与原因。
- primaryAction：动作名称、位置、是否会变更状态、是否需要付费/对外授权；每个活动视图恰好一个显著主动作。
- blockers + prerequisites：缺什么、怎么补、补完返回的准确节点。
- bindings：ProductTruth、ResearchBrief/参考集、ProductionAssetSet、Script、DirectorPlan、Clip、Prompt、Timeline、Final Artifact 的**版本/哈希**及生效范围。
- recovery：同一 taskId、stepKey、assetKey/clipId 的恢复标识和回程；不得相信任意 returnTo URL。
- publishedArtifacts：已确认成片和可信发布回执的独立状态、版本，不能与新生成任务进度混为一谈。

工程规则：
1. 网页所有“下一步/进度/按钮”只使用统一 WorkflowReadModel。旧导航可保留为兼容计算源，**不能独立再渲染另一个互相矛盾的推荐下一步**。
2. 默认恢复当前明确绑定的活动任务；多个活跃任务展示选择器；无任务才根据项目真实状态提出“继续旧流程/新建任务”。
3. GET 查询、打开抽屉/切页无业务写操作。用户确认/提交的 POST 带幂等键、版本前置条件、权限校验；不允许重复提交不确定远端请求。
4. 每次完成人工审核，服务端返回更新的 nextAction 和受影响版本，UI 立即更新当前任务局部区域；不要求人工“刷新本轮内容”。
5. 修改剧本、分镜、资产提示词、剪辑时显示受影响的下游版本范围，仅失效真正依赖项；单镜头重做不能作废其他镜头/已确认成片。
6. Seedance 原生音频/no BGM 与后期背景音乐、TTS、字幕是**不同设置层**；页面明确是否会进入最终成片、允许试听。
7. Model capability 的缺项只阻断依赖它的步骤，并用用户可读中文解释；其自动发现/路由仍按独立 TODO 设计，不借本轮重写。

## 6. 新设计必须逐一覆盖的异常与恢复场景

- 无产品资料/只有文字没图/已确认产品事实：仅提示缺失对象，补完回原任务。
- 未研究/抖音研究失败/登录过期/参考视频不可分析：展示原因，允许跳过非必选研究，不能让整个项目卡死或悄悄采用不可信参考。
- 多项资产可并行、有关联的按 DAG 顺序；单项失败只影响依赖链；真实图片始终可预览、提示词单独可编辑、重做必须重新授权。
- 正在生成的视频关闭浏览器又打开：读取原请求与提交编号，不能重复提交。
- 第 3 镜头重做：只更新第 3 镜头预检/批准/素材绑定；第 1、2 镜头及旧成片保留。
- 多个活跃 Run：明确当前任务选择，不能用“最后更新”偷偷切换用户任务。
- 旧项目已发布、但新 Run 正在审片：分别显示“历史成片已发布”和“本轮镜头待审”，不能出现含糊的项目整体状态。
- 已有成片只剪辑/发布：绕过不需要的创意和生视频；可信成片和发布回执必须版本绑定。
- 模型只有文本、没有识图：需要识图时直接指出缺能力，允许配置/跳过可选项，不返回模糊技术异常。
- 刷新、返回、跨项目切换、断网、服务重启：不丢原 run/clip/asset，上下文和版本；外部不确定结果不自动重试。
- 未经确认的真实积分使用、发布、评论回复：操作数量为零，重要授权分开、留痕。
- 顶部/弹窗不应自动关闭用户已打开的研究/登录浏览器窗口。

## 7. 分期实施方案及 Gate（未获授权不执行）

### UX-R0｜先冻结“纸面用户路径 + 页面原型”（当前阶段）
- 输出：6 种目的 × 条件/错误/人工确认矩阵、统一界面线框、全套状态与下一步文案表、旧版迁移策略、组件拆分表。
- Gate：让用户直接看页面原型并选择认可；必须回答“当前做什么、已做什么、下一步做什么、失败怎么恢复”。**不批准则不写业务代码。**

### UX-R1｜统一 WorkflowReadModel、错误词汇和任务选择
- 接入底层 Project、SmartRun、Timeline、Final 等真值，只做用户层投影；添加必要的明确活动任务绑定，不造第三套业务状态机。
- Gate：所有页面使用同一 nextAction；真实样本的“已发布 + 新审片”“已确认事实 + 旧创意”“多个 Run”不互相打架。

### UX-R2｜重构项目工作台与创建/继续分离
- 新建任务：展示按目的选择；已有活动任务：首屏只显示当前任务和一个主操作。
- Gate：1366×768 桌面首屏应看到当前动作；页面无重复主导航；不会因点击辅助工具误触新建/付费。

### UX-R3｜按业务操作抽取局部组件，完全取消完整页 iframe
- 产品事实、研究/素材、创意、角色/场景资产、剧本、分镜、Prompt、审片、音轨、最终 QC 分批迁入同源局部组件；保留专家完整页作为次级入口。
- Gate：主工作台内不含完整页 iframe；关键节点提交后局部刷新，原任务原 clip/asset 位置保留；编辑能即时看到版本影响。

### UX-R4｜历史项目与异常恢复、安全回归
- Legacy 兼容运行，不对旧审批或历史任务强行迁移；老项目可选择“继续旧任务”或安全创建新任务；修复状态错误和重复操作风险。
- Gate：不重复付费、不丢已生成视频、不重发作品、不覆盖原 Timeline；一镜头重做不会使其他镜头失效。

### UX-R5｜真实场景验收与渐进发布
- 保留旧版作为可切换回退基线；先在测试环境/样本项目验收，再由用户允许开启正式新工作台。
- Gate：原自动化测试继续全部通过，新增用户流程回归必须通过；未经批准不做真实积分生成/发布验证；问题可一键退回旧界面，不改变历史产物。

## 8. 必须加入的硬性质量门禁

1. **禁止旧错误成为验收标准**：测试中明确断言“工作台内完整文档 iframe 数=0”，不再写 iframe/src 存在为 PASS。
2. **功能操作闭环**：不是仅测试链接 href；模拟从启动到确认结果的真实动作以及状态自动返回，不依赖“手工刷新本轮内容”。
3. **唯一下一步**：当前阶段一条醒目主行动；辅助功能可见但不和主任务争优先级；所有页的状态与同一只读 API 一致。
4. **不可绕过授权**：自动规划允许；Seedream/Seedance 新付费、重复生成、发布、评论回复必须独立确认；GET、切页、刷新触发的外部写入为 0。
5. **用户测试**：至少安排 3 名未参与实现的测试者，在不解释内部路径的情况下完成：从零创建→选择创意、研究参考→继续、资产确认→继续、审片→重做指定镜头、已有成片→发布准备，任一人卡在不知下一步即 Gate 失败。若没有独立测试者，不能宣称“用户体验验收通过”。
6. **异常完整**：12 类场景矩阵全覆盖，包括无能力模型、远端结果未知、历史发布、不同 Run、浏览器刷新/重启与跨项目。
7. **上线可回退**：任何旧数据不强制迁移、不清理用户未提交改动、不强制重建全项目；新 UI 开关与校验记录明确。
8. **视觉检查**：桌面 1366×768 与小屏 390px 至少各跑主要步骤，逐页截图审核，不能只依赖 DOM 断言。
