# 待设计与开发：Product Video Studio 按制作目的统一工作流与操作路径

- 记录日期：2026-10-08
- 所属项目：Product Video Studio / PVS × 抖音运营
- 优先级：高（真实测试中频繁跨页面、返回后找不到下一步；影响可用性）
- 状态：**W0–W4 确定性工作流改造已完成本地开发，476/476 单元/集成和 20/20 浏览器 E2E 全部通过，正式 3090 网页已部署并只读验收；真实外部付费生成与平台发布不在未授权测试范围内**
- 路线决策：**先做确定性 Workflow 编排与 UX 衔接，不实施完整自主 Agent / Agent Runtime / 多智能体决策架构**。
- 用户原始反馈：不同目的和特殊情况操作时总在页面之间跳来跳去，缺乏明确、连续、可恢复的制作步骤；之前讨论过多场景步骤梳理，现在确认应改进。

## 一、目标与边界

1. 用户**按目的开展任务**，而不是先学习研究页、参考视频页、智能生成页、旧生成页、时间线、发布设置等模块如何手工串联。
2. 程序依照固定、可解释、可恢复的业务工作流自动推进已明确允许的非付费步骤；**用户只在确实必须确认的节点作决定**（事实、创意、角色/场景资产、费用、低置信视频、成片、发布、作品绑定等）。
3. 所有节点要统一提示：「现在在做什么、为什么等待、需要用户做什么、完成后去哪、哪些步骤已完成/可跳过/尚不可用」。
4. 尽量以**项目当前任务**为统一入口和进度页；研究、参考视频、资产、剧本、分镜、Prompt、审片、时间线等依旧保留完整功能及专业编辑，而不是靠隐藏高级编辑或删减功能来解决跳转。
5. 不重复实现底层生成或剪辑引擎；优先复用现有 SmartGenerationRun、WorkflowNavigation、TaskCenter、ProductionAssetSet、Preflight、Review、Timeline、Render、Publish、DouyinOps 等服务。旧兼容模式/已提交任务/历史项目不能被破坏。
6. 当前先进行工作流重构，不开发“AI 自主理解目标并自由规划工具调用”的 Agent 方向。现有 AI 在创意、剧本、导演、检测等步骤的能力可继续调用，但由业务工作流负责控制进度。

## 二、必须覆盖的不同目的入口

| 目的或情景 | 建议主流程（必要步骤与可选步骤按条件出现） |
|---|---|
| 从零制作产品视频 | 新建/继续项目 → 产品资料/事实 → 创意选择 → 制作策略与资产 → 剧本/分镜与视频提示词 → Preflight → 明确付费授权 → 生成 → 审片 → 自动/手动剪辑 → 质检与成片 → 发布 |
| 抖音爆款/同类竞品参考创作 | 产品资料 → （可选）深度研究/同类爆款搜索 → 选择研究样本 → （按需）取得参考素材/拆解 → 明确审核资料与创作参考 → 导入同一制作任务 → 继续创作 |
| 用户已有参考视频 | 上传、预览并分析 → 确认引用的参考视频与拆解结果 → 自动带入当前任务 → 继续创意与制作；无需来回寻找“导入智能生成” |
| 剧情类多镜头广告 / Director V3 | 分镜前按依赖准备与确认角色/场景素材 → 可查看/编辑脚本、镜头合同、Prompt → 模型能力与时长检查 → 按镜头生产 → 审片、剪辑 |
| 只生成单个视频片段 | 明确“单片段生成”独立入口，避免误以为是完整一键成片；不强迫进入全片的剧本/剪辑/发布流程 |
| 某一镜头不满意、想重做 | 在该镜头原位选择“采用/重做/跳过” → 必要时原位修改 Prompt 与绑定素材 → **仅重检该镜头** → 重新确认新增付费范围 → 生成与审片 → 回到原任务原镜头与进度 |
| 资产失败、结果未返回、需要重新生成 | 原位展示各资产真实图片、提示词、依赖与进度 → 允许局部恢复、修改、明确新付费授权；其他独立资产不重做；远端提交未知禁止直接重提 |
| 重新编辑已有视频/已有 Timeline | 进入已确认素材与时间线，重剪后保留历史版本 → 质检/渲染，不重新运行不相关的创意和视频生成 |
| 已有成片只需要发布 | 进入成片审核/发布流程，复用有效 MP4、发布前质检与明确发布确认，不强制重新制作 |
| 发布后作品运营 | 根据**可信发布确认状态**提供进入当前项目抖音运营入口 → 绑定真实作品 → 指标/评论/复盘；不得自动错绑、重复发布、自动回评论 |

## 三、统一工作流体验的实施建议

1. **一个当前任务上下文**：新任务/恢复任务可以明确选择目的和继续位置；从研究、参考视频、审片等辅助页返回时保留 projectId、smartRunId/当前任务、stage、clipId/assetKey、原用户操作与滚动定位等必要上下文。
2. **主流程步骤条及“唯一主操作”**：每个状态从后端统一得到 currentStage、nextAction、nextRoute、reason/blocked、returnTo、paidConfirmationRequired；根据条件动态插入/跳过研究、资产、音频、发布等节点，不向用户展示多套相互矛盾的“下一步”。
3. **原位处理优先**：智能生成页面直接提供必要的素材确认、剧本/导演/Prompt 编辑、选片和异常修复入口，优先抽屉/嵌入子页面；确实需要独立页时自动携带返回地址并提供“处理完成并继续原任务”。
4. **确定性状态机**：协调目前项目 `Project.status`、`SmartGenerationRun.stage/status`、`WorkflowNavigation`、`TaskCenter`、`ReviewDecision`、`Timeline`、发布状态；为同一个任务产生一致进度和下一动作，禁止前端单独推测已完成或已发布。
5. **跨功能前置 Gate**：只有实际需要的参考资料/产品主图/角色场景、模态能力、费用与版本完整性才阻止对应步骤；阻塞原因用中文并提供可执行操作。执行失败或重新打开浏览器仍回到真实断点，不重新提交已成功的付费内容。
6. **保留完整专业控制**：允许修改创意、剧本、分镜、生成提示词、制作资产提示词、视频裁剪、字幕、音轨、时间线；明确展示改动可能使下游哪些结果失效，保存时保留版本与回滚。
7. **付费与外部动作安全**：自动推进的非付费步骤和提交 Seedance/Seedream、抖音发布、评论/回复等必须分离；每次新的明确付费范围及对外写入都须单独确认；结果未知不得重复提交。
8. **发布/运营衔接**：与已有 `TODO-POST-PUBLISH-DOUYIN-OPS-ENTRY-2026-10-08.md` 联动，可信发布成功后自然流转到对应项目运营，而非跳到不相关的全局页面。
9. **面向用户的中文文案**：不以内部英文 stage、UUID、hash、API 错误作为主界面步骤；技术信息可展开，不影响专家调试。
