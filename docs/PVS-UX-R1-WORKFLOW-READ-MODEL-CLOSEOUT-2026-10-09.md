1. 新增纯函数 `src/application/services/workflow-read-model.ts`：只读合成现有 Project.status 与 SmartRun.status/stage，按六组用户可理解阶段展示，并生成与旧版兼容的下一操作。此层是用户展示投影，不是新一套自动执行状态机。

3. 多个同项目未结束 SmartRun 不再默选最新；用户必须选择。前端支持 `?activeRun=<id>` 精确上下文，对不存在、跨项目或已结束任务拒绝自动切到其他任务；旧项目仍然可根据已有状态安全继续。
4. 将项目历史 `PUBLISHED` 标记与当前 SmartRun 进度分开显示。注意：只读投影**不查询可信发布回执**，明确标注 `receiptVerification=NOT_CHECKED`，不能把旧项目状态当作本轮真实发布成功。
5. `GET /api/projects/:id/workflow` 继续只读，支持精确活动任务选择；POST 依旧 405，展示不生成新请求。
6. `/projects`、`/projects/:id/smart`、产品事实/旧项目专业页面、研究/参考视频/模型设置/单视频页面统一读取同一投影后的下一步，保留原有实际业务控件。
7. 回到原任务的链接带精确 `activeRun` 参数，避免多个任务场景回到错误任务；不允许任意第三方 returnTo URL。
8. 项目无活跃 SmartRun 时，读取真实 `Timeline` 和 `FinalAssembly` 最新状态及所属 ProductionPlan hash。已确认或已渲染的当前版本优先于滞后的 `Project.status`；历史旧计划哈希不匹配时不借用其结果。所有读取均由原存储的只读方法提供，不新建剪辑或成片。
